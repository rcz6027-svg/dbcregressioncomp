This is an explanation for our final model using trees.

The first two lines simply make copies of the X_train and X_test values and changes the data type to categories. This is because it is compatible with the HistGradientBoostingRegressor because it can split these datas automatically without having us make a pipeline with an imputer and transformer.

The boosted_trees function returns the model with the parameters we give it, we made it a function because we wanted to use CV and folds to test out six different parameters of the model function to see which one works best (though the difference ended up being minimal). 

We have a wrapper on the model's code itself which converts the final predictions into log values for inputs and exponent values as an output, this keeps the error in percentage terms which is better so that way 20,000 dollar error on an expensive house is not considered the same as 20,000 dollar error on a cheaper house.

HistGradientBoostingRegressor is our actual model itself. Based on our understanding, it works by first creating a larger decision tree that groups houses into final groups called leaves based on various yes or no questions related to the data in the columns (e.g. is OverallQual >= 6?). It then uses the average of those leaves to predict the value of individual houses that are apart of the leaf. So, initially it gives every house the equivalent, crude prediction of a certain value. It then takes the average errors of those predictions to use in the next tree. The way the model learns which columns and which column values correspond to higher or lower prices is by creating more and more trees with different progressions of questions which are then used on the previous trees' errors to slightly correct the predictions. For example, initially the origin tree may predict every house at a mean value of, hypothetically, 160k, and then it calculates the error of each, aka real - prediction to use for the next tree. Then the next tree will make its own unique set of questions leading to more unique leave groups and using the errors from the first tree it can then determine what factors are being over / undervalued and consequently which factors increase or lower the value of the house. For example, the second tree may discover that houses of OverallQual above 8 are being overvalued, those of value 6 or 7 are being undervalued, and those below 6 are also being undervalued. The second tree then applies that error onto the original prediction number which is representative of it accounting for how that factor or combination of factors in the leaf actually impacts price. Though, we don't apply 100% of the correction because this would lead to more errors down-the-line (due to the small scope of each individual tree) and also would cause overfitting. 

Explaining the specific parameters we chose to use in this HistGradientBoostingRegressor. We chose a learning rate of 5% (aka how much of the error is applied to the next tree and final prediction) so as mentioned previously the model corrects in small steps and doesn't overshoot things. The max iteration aka how many trees was 600 which was just arbitrarily selected between a certain range because we didn't want to do too many or too little because with too little it is not enough to create a generalized model and too much is simply diminishing returns. Max leaf notes of 15 ensures that each tree has a maximum of 15 different groups at the end. This is because since we are taking the mean at each leaf and using that for error calculations if we had a very small amount it would be inaccurate because again, you cannot generalize overall a small sample. l2 regularization is functionally used to eliminate the impact of variance and outliers, though honestly we are not sure of the exact mathematics going on behind the scenes. Max features determines how many columns a tree is allowed to use, in this case we allowed it to use 100%, 50% or 30%. There is a significance to this as 100% doesn't actually functionally make a decision tree with 2 to the power of 79 decisions because of the limiter we put on with the max leaf nodes of 15. Therefore 30% allows for more variance, honestly if we tried out different max leaf nodes or different learning rates or different max features it may have leaded to even different results, curious to try that out. Similar to max leaf nodes, min sample leaf just ensures that every leaf at the end of of a tree has a least 20 houses in it, and this is because it necessary for generalization to have at least a decent sample size. Random state as we saw in class is just to ensure the same values get output each time even though the model has some inbuilt variance.

The sweep list and the loop that appends it just tests out 6 different combinations of how much columns we give each tree (max features) and how many houses were required to be in each leaf (10vs20), just to see if it makes any reasonable difference to see if we can make an even more accurate model. And for each model we also apply the idea of folding, in this case with 5 splits meaning for each model it fits on 4/5 of the data and then predicts the RMSE of each before taking the mean of all of them to get the most realistic rmse value. They all get appended to a list before being sorted numerically by RMSE value so that way we can simply display the index 0 of the sweep list to get the model which had the best RMSE results (aka lowest final RMSE). This ended up being the one with a minimal house number per leaf of 20 and with trees that only could use at maximum 30% of the columns data.
